# 文本识别系统

将用户提交的营销需求文字或截图转换为二级设计页面左侧表单可直接使用的结构化字段。

## 使用方式

1. 阅读 [字段规范](references/field-schema.md)，确认目标页面支持的字段与枚举。
2. 有图片时阅读 [图片 OCR 规范](references/image-ocr.md)，先调用 `scripts/recognize-images.mjs` 中的 `recognizeImages(images)`。
3. 将用户输入文字放在 OCR 文字之前合并，再调用 `scripts/extract-text.mjs` 中的 `extractDesignBrief(text)`；不要重复编写另一套映射规则。
4. 使用返回的 `values` 填充表单；未返回的字段必须保留页面当前值。
5. 如需向用户解释结果，可使用 `confidence` 和 `evidence`，但不要把 OCR 或语义推断说成用户明确提供的内容。

## 识别原则

- 明确标签优先于语义推断，例如“主标题：”“营销类别：”“权益01：”“按钮文案：”。
- 无标签时，根据节日、促销、日常场景关键词识别营销类别。
- 根据有效权益数量和“单 Offer / 双 Offer”等明确表述识别 Offer 类型。
- 金额、折扣、满减、免息、买赠等权益值与其周边说明文案分开提取。
- 只在文案明确出现时识别生成数量和生成质量。
- 不确定时留空，不虚构标题、权益、CTA 或营销类别。
- 同时存在手动输入和图片时，手动输入优先；图片文字用于补充未明确提供的字段。
- 多张图片按上传顺序识别，复用一个 OCR worker，避免重复加载语言模型。

## 输出边界

- 返回页面字段值，不负责生成最终图片或改写营销文案。
- 不覆盖用户已填写但本次文本未识别出的字段。
- 当前枚举必须遵循字段规范，不创建页面不支持的新类别或新质量等级。
- OCR 失败时不得丢弃可用的手动输入；只有图片且无法提取文字时，应返回可理解的失败信息。
