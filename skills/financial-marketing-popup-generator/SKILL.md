# 首页弹窗设计规则

将业务文案与主题组合成固定信息布局的营销弹窗。保持金融产品的稳定、清晰感，主题变化体现在有细节的顶部插画组合、有序花边、灵活分色和少量点缀。

## 读取规则

生成或修改前，读取 [规则入口](references/skill.yaml) 和其中所有 required 模块。入口内的 `rules/` 与 `examples/` 路径均相对于 `references/`。检查已有素材时，先读取 [校验规则](references/rules/validation.yaml)，再按检查项目读取相关模块。

规则优先级：validation → layout → cta → typography → top-visual → colors → edge-language → graphic-style → 主题示例。低优先级配置不能覆盖锁定值。用户本轮明确要求更改规范时，以用户要求为准，并说明结果偏离了哪些原规范；不要将偏离结果标为原规范合格。

[主题示例](references/examples/themes.yaml) 仅在选用圣诞、万圣节、电商大促或需要参考主题结构时读取，不限制用户选择其他主题。示例不是默认业务文案。

## 输入与内容

从用户消息和现有素材提取主题、标题、利益描述、Offer 主值/百分比/后缀、CTA 文案；仅询问实际缺失且影响结果的信息。Offer 不适用的字段可以明确留空。业务数值、利率、折扣、承诺和有效条件不能凭空补齐；仅做视觉草案时可使用明确标注的占位文案。

文案放入既定槽位。利益描述和 Offer 辅助文字在既有 Offer 区域内排版，不另增会挤压固定框的布局。原规则未锁定字号，按可读性选择字号与换行；标题最多两行。若容纳不下，提出文案压缩建议，不擅自改变业务含义、移动框或压扁文字。

## 视觉方向：以用户参考为准

制作前查看 [用户设计参考](assets/design-reference.png)，理解顶部主题组合、共同外轮廓、上下直接分色及有序花边的关系。参考图不代表解除 CTA 净空、品牌配色或固定几何限制。

默认在同一张卡片外轮廓内做上下两段大面积分色，可按主题调整，不强制三个色块。标题与权益是隐形排版安全区，不是必须绘制的容器；背景颜色可以铺满卡片宽度。不要默认套“标题矩形＋权益矩形”。若选择框式方案，用协调的裁切、点线或主题纹样包装。分色交界可加一条克制的锯齿或织带纹样。

花边位于左、右、下三边。简单圆瓣、三角裁切与重复节奏可以成立；允许少量内侧点线或有意叠色（不能造成轮廓接缝错位），不强制内部镂空。选择一个主轮廓，至多一种辅助纹样，避免密集小孔和三边同强度的复杂花纹。具体方案见 [花边规则](references/rules/edge-language.yaml)。在实际尺寸判断疏密，不把“墨西哥剪纸”理解为越复杂越好。

顶部保持纯色矢量扁平小插图。丰富度来自色面叠放、内部图案、配件和遮挡，例如礼盒包装图案、扁平蝴蝶结、铃铛和松枝的组合。禁止渐变、光泽、材质模拟、立体明暗和3D渲染，不能把“丰富”转化成复杂写实插画。顶部50%宽度、居中与卡片后方层级保留。

花边数量按每条边上的完整重复轮廓单元计算：左、右各7–9个，底部5–7个；通用上限范围为每边5–10个，具体执行以前述左右/底部范围为准。转角单独收口，不计入重复数量；点线、内部图案不作为额外轮廓单元计数。

先预留转角连接，再均分直边排布重复单元。花边沿左、下、右自然转弯，保持整体连续轮廓，不能拼贴边条后留下半个单元、错位、凸块、尖刺或断口。上下色块共用同一外轮廓裁切。交付前逐边核对数量，并在原尺寸及4倍放大下检查两处底角和侧边顶部收口；曲线转角检查切线衔接，折线转角检查有意对齐的转折。

标题和权益文字框四边各内缩5px。色彩背景不受这些文字框限制，装饰与裁切不得进入文字安全区。多方案要在轮廓/分界纹样/分色关系/顶部组合上体现区别，避免仅换颜色。

## 制作约束

精确数值以引用的 YAML 为准，尤其注意：

- 透明画布 279×400；卡片 (30,65,219,240)、可选标题框参考 (40,82,199,55)、标题文字安全区 (45,87,189,45)、可选 Offer 框参考 (40,158,199,115)、Offer 文字安全区 (45,163,189,105)、CTA (21,326,237,44)。
- 顶部视觉整体含配角和点缀，逻辑宽度严格 109.5，水平中心 x=139.5，位于卡片后方并被遮挡。整数栅格可见宽度按原规则使用 109 px，不向上取整。不要把逻辑宽度和抗锯齿像素范围混为一谈。
- CTA 为 #1A55FF、白字、半径 22 的胶囊，独立图层与文件。y=305 至画布底部的区域除 CTA 外必须空白；卡片花边也不能伸入该区域。
- Offer 是第一视觉重点。卡片分色和 CTA 用纯色；顶部也保持纯色矢量扁平，禁止渐变、光泽、立体明暗、材质和真实投影。核心色为 #FFA423、#FF5290、#008CFF，辅助色与其相邻，基础有彩色不超过四种（含 CTA），通过色面组合而非模拟光照增加丰富度。
- 可见文本只能使用 Roboto，并遵守角色字重。生成前确认字体和所用字符可用，不能偷偷使用系统回退字体；中文等缺字情况应说明冲突并请求可行文案或用户明确调整字体规则。包内不附带字体。

选择能控制坐标、图层、字体和透明导出的制作方式。对规则明确的几何图形优先使用可编辑的矢量或程序绘制；若使用图像生成，仅作为主题图形素材来源，不能假定生成的文字、尺寸、字体和切图满足精确规范。没有可用的精确渲染或字体环境时，交付可检查的规格/源文件并说明未完成项，不伪称已完成合格切图。

## 交付与检查

生成成品时提供：

1. `composite_preview`：279×400 透明合成预览。
2. `card_group`：包含顶部视觉、卡片和全部卡片文案，排除 CTA；保留坐标定位信息，裁切时说明相对原画布的偏移。
3. `cta_asset`：独立 237×44 透明背景切图。

保留可复查的源文件或布局信息，便于验证逻辑坐标、图层与字体。若用户只要求提示词、规格或审核，则交付相应结果，不强制制作图片。用户明确只要 JPG 看效果时，只交付 JPG 预览，用明确的浅色背景替代透明背景，不强制交付独立切图，也不将 JPG 当作透明生产素材。

导出后按 [校验规则](references/rules/validation.yaml) 检查。优先依据源场景结构，其次导出元数据，再次栅格分析；同时查看实际渲染的透明度、裁切、可读性、遮挡和视觉层级。不要凭肉眼宣称坐标或字体精确通过。

命中硬拒绝项时先修正再复查；无法修正则标记未通过，并给出原规则错误码和具体原因。证据不足的项目标记“未验证”，不能算通过。简短区分已通过、未通过和未验证项；有缺陷的预览只能作为草案，不标成可投放成品。
